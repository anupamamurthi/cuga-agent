# User Story Format

Always write user stories in this structure:

**Title:** Short imperative phrase (e.g. "Rate-limit API endpoints")

**Story:**
> As a [persona], I want [capability], so that [benefit].

**Context:** 1-2 sentences on why this matters now.

**Constraints:** Technical, legal, or business constraints that shape the solution.

**Dependencies:** Other stories or systems this depends on.

Rules:
- One story = one testable behaviour
- If a story takes more than one sprint, split it
- Persona must be a real user type (not "the system")
