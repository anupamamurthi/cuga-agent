# Sprint Planning

When planning work into a sprint:

- Team velocity is the primary input — do not overcommit
- Every sprint must include: new feature work (60%), tech debt (20%), buffer (20%)
- Stories need all fields complete before sprint start: AC, estimate, assignee, dependencies cleared
- Identify the one story that, if delayed, would block everything else — that's the critical path
- Flag any story with external dependencies (another team, third-party API) — these need a fallback
- Definition of Done: coded + reviewed + tested + deployed to staging + demo-ready
